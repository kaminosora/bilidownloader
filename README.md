# Bili 本地下载

纯 Chrome 扩展：在 B 站播放页选择视频、音轨与保存格式，使用浏览器内置的本地处理模块下载和转换。日常使用不需要 Node、Python、本地服务或额外启动程序。

## 安装预构建版本

需要 **Chrome 116 或更新版本**。

1. 本项目已经构建时，打开 `chrome://extensions`，开启右上角「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择 本项目的 **`dist` 文件夹**。该目录根部应有 `manifest.json`。
3. 若使用发布 ZIP，先解压 `release/bili-local-downloader-1.0.1.zip`，选择解压后含 `manifest.json` 的 `bili-local-downloader-1.0.1` 文件夹。保留该文件夹，不要直接加载 ZIP。
4. 刷新已打开的 B 站视频页面。可在 Chrome 扩展菜单固定「Bili 本地下载」。

更新时用新版本替换扩展文件，再在扩展管理页点击「重新加载」并刷新播放页。请先等待任务完成，重新加载扩展可能中断任务。

## 下载视频或音频

1. 打开 `https://www.bilibili.com/` 下的 BV / av 视频或 ep / ss 番剧播放页，先确认网页能完整播放。需要账号权限的资源，应先在正常网页登录。
2. 点击页面右下角「下载」，或点击扩展图标后选择「打开当前页下载面板」。
3. 选择分 P / 剧集。**面板选集只改变下载内容，不切换网页播放器**；以面板显示的标题、分 P 和剧集为准。网页自身导航时，面板会重新读取当前页。
4. 选择「视频」「音频」或「原始轨」，检查资源与格式，再提交任务。画质下拉只列出本次响应中有实际资源的画质；视频编码与音轨按接口返回展示。
5. 在面板或「全部下载任务」查看进度、取消或重试。Chrome 将文件保存到当前下载目录的 **`BiliLocal`** 子目录；同名文件自动添加序号。
6. 任务产生下载记录后，点击「打开所在文件夹」即可通过 Chrome 在系统资源管理器中定位文件。双轨任务会选择其中仍存在的已完成文件；文件尚未完成、已移走/删除或记录已清除时显示提示。

关闭面板和视频标签页不会主动取消任务；请保持 Chrome 运行。浏览器会话结束后，未完成任务可能标为中断，需要重试。一次执行一个任务，最多排队五个任务。重试会重新获取资源；若源站的可用轨发生变化，请回播放页刷新并重新选择。

| 模式 | 格式 | 说明 |
| --- | --- | --- |
| 视频 | MP4、MKV | 保留所选视频编码并无损封装；有独立音轨时合并。源轨缺少声音时会提示。 |
| 音频 | 原始、M4A、MP3、WAV、FLAC | 原始音轨保留编码，先写浏览器临时存储再保存；AAC 转 M4A 可无损封装，其他编码导出 M4A 会转成 AAC。MP3 属于有损转换。 |
| 原始轨 | 原始视频轨、音轨、分别保存 | 扩展流式下载到浏览器临时存储，完成后由 Chrome 保存本地文件。分离视频轨通常没有声音；音画合一资源保留原始文件。 |

**文件容器与编码是两件事**：MP4 不等于 H.264，MKV 也不等于某种画质。AVC、HEVC、AV1、AAC、杜比或 Hi-Res 是否可选，取决于实际响应和当前账号权限。某音轨不能无损放入 MP4 时，改选 MKV。转换为 FLAC / WAV 不会增加源音质。

旧式音画合一资源没有独立音轨时，「音频」默认使用 M4A 等导出格式，需要下载完整原始视频后提取音频；不提供不存在的「原始音轨」。

## 大文件与使用边界

合并和转换的**输入文件合计上限为 512 MiB**，不是输出文件上限。长度未知时按已下载字节检查。浏览器处理时还需要额外内存，因此低于上限也可能因内存不足失败。

较大文件可改用「原始轨」分别保存；「音频 → 原始音轨」也使用相同方式。扩展将媒体流式写入浏览器的私有临时文件区（OPFS），下载完成后再交给 Chrome 保存到下载目录，保留原始字节、不经过 FFmpeg。**原始轨不受 512 MiB 合并 / 转码输入预算限制，但受可用磁盘空间和浏览器存储配额限制**。保存阶段临时副本与最终文件可能同时占用空间。

临时文件在保存完成、失败或取消后清理；异常退出留下的临时文件会在下次原始轨任务开始时清理。原始轨不直接把 CDN 地址交给 Chrome 下载管理器，也不提供跨浏览器退出的断点续传；中断后请重试，重新获取资源并下载。

仅处理当前账号已取得的未加密资源。不支持 DRM 解密、权限或地区限制绕过；试看 / 不完整资源会报错。网页可播放不保证扩展一定可下载。首版不提供直播、收藏夹批量下载或互动分支遍历。

FFmpeg 的 JavaScript、Worker 和 WASM 随扩展打包；音视频不会上传到转换服务。数据与权限细节见 [PRIVACY.md](PRIVACY.md)。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 无入口或提示扩展连接更新 | 确认地址为 `https://www.bilibili.com/video/...` 或 `/bangumi/play/...`，在扩展管理页检查加载错误，再刷新播放页。首页、移动域名和短链接不直接显示面板。 |
| 要求登录、账号或地区无权限 | 在 B 站原网页登录并确认完整播放，再「重新获取资源」。扩展不新增会员、购买或地区权限。 |
| 403、风控、请求被拒绝 | 稍后低频重试；确认网页可播放。扩展只为自身到允许域名的请求设置 B 站 Referer；源站仍可能拒绝。不要复制 Cookie 或修改系统代理来处理扩展问题。 |
| 资源过期 / 所选轨已变化 | 点击重试会刷新链接；若仍失败，回面板重新获取资源、重新选择画质和音轨。 |
| 视频无声 | 检查是否保存了分离视频轨；使用「视频」合并模式并选择可用音轨，或同时保存原始音轨。 |
| 不兼容 MP4 | 选择 MKV 保留原始轨，或单独导出音频。扩展不会静默换轨或降低画质。 |
| 超过预算、处理失败或内存不足 | 改用原始轨；关闭不必要标签页后重新提交较小内容。取消后可继续其他任务。 |
| 原始轨提示磁盘或存储配额不足 | 为浏览器临时存储与最终文件同时留出空间；释放磁盘空间后重新提交较小内容。关闭标签页不能增加磁盘配额。 |
| 显示保存但找不到文件 | 检查 Chrome 下载管理器及下载目录中的 `BiliLocal`，确认磁盘空间和浏览器保存提示。 |

## 开发者重建与验证

使用 Node.js 24 LTS；Python 3 仅用于生成 ZIP。以下 PowerShell 命令在项目根目录执行：

```powershell
# 先进入克隆或解压后的项目根目录
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.cache/ms-playwright'
npm ci
npx playwright install chromium
npm test
npm run build
npm run test:browser
# 可选：访问一个真实公开视频，验证匿名下载和合并
npm run test:live
# 审阅 docs/TEST_REPORT.md 和 test-results/ 后再生成发布包
npm run package
```

`.npmrc` 将 npm 缓存放在项目内 `.cache/npm`；上述浏览器安装放在 `.cache/ms-playwright`。浏览器测试使用 `test-results/` 内独立配置、合成素材与下载目录，不使用日常 Chrome 个人资料。`package-lock.json` 锁定依赖及 npm integrity；构建复用已固定版本的第三方 WASM，不重新编译 FFmpeg 核心。

浏览器及实站测试另外需要测试机 PATH 中的 `ffmpeg`，用于独立解码检查输出，也可通过 `FFMPEG_TEST_BINARY` 指定完整路径；此工具只用于开发验收，扩展日常运行使用自带 WASM，不需要它。实站测试会真实下载一个匿名可访问的视频及音轨，并在测试退出时移除 Chrome 临时下载；保留测试统计，不记录媒体地址。

打包生成 `release/bili-local-downloader-1.0.1.zip`、`release/bili-local-downloader-1.0.1-source.zip` 和 `release/SHA256SUMS`。源码包只收录源码、静态资源、测试夹具、文档、脚本和依赖清单，不包含缓存、个人资料、测试下载、`node_modules` 或 `dist`。源码 ZIP 中包含本扩展完整源码；第三方核心的上游源码与构建来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

可用 `Get-FileHash -Algorithm SHA256 .\release\*.zip` 与 `SHA256SUMS` 对照。`node scripts/package.mjs --check` 只检查打包输入与清单，不生成 ZIP。

具体已执行项目、结果和未覆盖范围以 [docs/TEST_REPORT.md](docs/TEST_REPORT.md) 为准。受控 API / 合成媒体的测试与匿名实站接口检查，不等于已验证登录账号、VIP、付费或地区受限资源；这些需要用户在自己的正常浏览器会话验收。
