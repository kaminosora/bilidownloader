# Bili 本地下载：纯 Chrome 扩展设计

日期：2026-10-24。状态：用户已确认，授权自主完成开发与测试。用户已选择“纯 Chrome 扩展，无需启动其他程序”。

## 目标与使用方式

用户通过 Chrome 的“加载已解压的扩展程序”安装本地目录。访问 B 站普通视频、多 P 视频或番剧/影视播放页后，可打开嵌入网页的下载面板，选择当前分 P/剧集、画质、视频编码、音轨和输出格式，保存视频或音频。扩展使用当前浏览器登录状态获取播放资源；不要求复制 Cookie，不另行启动服务。

“任意格式”指接口实际提供给当前账号的可下载、未加密播放资源。界面动态展示结果，不把站点公布的画质名称等同于账号已经取得该资源。原始编码可能包括 AVC/H.264、HEVC/H.265、AV1；音轨可能包括 AAC、杜比音轨、Hi-Res/FLAC，是否出现以资源响应为准。容器与编码分开呈现。

## 已比较的实现方式

1. 纯扩展：Chrome MV3 + 内置 FFmpeg.wasm。安装和日常使用简单，完全在浏览器本地处理；合并、转码受到浏览器内存限制。用户已选择此方案。
2. 扩展 + 本地 FFmpeg 助手：更适合大文件和长时间任务，但需要额外启动程序。用户未选择。

以下技术细节由实现者提出，用户可以在确认时修正。

## 首版功能

- 网页右侧的可折叠下载入口；Shadow DOM 隔离页面样式。弹出窗口提供连接当前页、打开任务列表和使用说明的入口。
- 识别 BV/av 视频、多 P、ep/ss 剧集页面；页面内部切换视频或分 P 后重新识别，避免使用上一集的链接。
- 展示真实可用画质、分辨率、帧率、编码和音轨信息。切换画质时重新获取资源；遇到权限不足、风控、资源过期或无媒体资源时显示明确错误。
- 视频：优先无损合并音视频，提供 MP4、MKV 输出；所选音轨无法无损放入某容器时给出可用容器，不能静默降画质或改音轨。
- 音频：可保留编码保存原始音轨；可在本地导出 M4A（兼容音轨无损封装，否则明确转换为 AAC）、MP3、WAV、FLAC。说明转成 FLAC/WAV 不会增加源音质。
- 大文件备用方式：先流式写入浏览器私有临时文件，再通过 Chrome 下载管理器分别保存原始视频轨与音轨；清楚标记分离视频轨可能没有声音。已有音画合一资源可保存原始文件。旧式分段资源可分别保存，受内存预算允许时合并。
- 单任务执行、有限队列、下载/处理/保存进度、取消、错误后重新获取资源再重试。关闭面板不取消任务；浏览器退出后不保证继续，重新打开后把未完成任务标为中断。
- 文件名包含标题、分 P/剧集、画质/编码或音轨信息，并清理 Windows 非法字符；保存不覆盖已有文件。

## 浏览器内处理限制

FFmpeg 与 WASM 资源全部随扩展打包，不从 CDN 加载远程可执行代码。使用单线程核心，避免多线程所需的跨源隔离依赖。原始音视频不上传到任何转换服务。

首版采用保守的 512 MiB 合并/转码输入总量预算；在内容长度已知时预检，长度未知时按已接收字节计数并在超限时终止，提示改用分别下载。预算是内存保护措施，不承诺预算以内必定成功。内存不足时释放任务资源并显示可操作错误。原始轨分别下载不受此处理预算限制，但仍受磁盘空间、浏览器存储配额、网络、Chrome 和源站限制。

禁止把 UI 上的“可观看”直接承诺为“一定能下载”：DRM/加密资源、登录/VIP/地区限制、站点拒绝请求或 API 改动应明确报错，不生成损坏文件冒充成功。第一版不提供 DRM 解密、不新增观看权限、不做全站/整个收藏夹批量爬取，不承诺所有直播或互动视频分支。

## 模块与数据流

1. 内容脚本：只负责嵌入面板、页面地址变化和用户操作，不读取或导出 Cookie。
2. 后台 service worker：校验消息来源和参数，调用限定的 B 站接口，解析元数据与播放资源，建立任务，操作 Chrome 下载管理器。
3. 资源解析模块：UGC 使用元数据与 WBI 播放接口，PGC 使用剧集元数据与播放接口；统一处理 DASH、杜比、FLAC、durl、备用 URL、质量标签和权限错误。WBI 签名逻辑用固定样例测试。
4. offscreen 页面及 worker：下载有限大小的媒体、运行随包 FFmpeg.wasm、维护正在执行的任务和 Blob。仅通过 runtime 消息与后台通信。最终 Blob 保留到 Chrome 下载完成或中断，随后释放。
5. 原始下载：offscreen 通过扩展自身的 fetch 下载经过验证的媒体，并流式写入 OPFS 临时文件。完成后从文件生成本地 Blob，后台交给 Chrome 下载管理器保存；需要的 Referer 规则限定为扩展发起且仅针对允许的 B 站媒体主机，避免改变普通网页请求。
6. 本地存储：保存非敏感任务摘要；摘要中不持久化 Cookie、签名媒体 URL 或音视频数据。媒体 URL 仅在当前任务内存中使用；原始媒体字节会暂存到 OPFS，并按任务生命周期清理。

后台处理短请求，长任务由 offscreen 页面承担；service worker 休眠/重启时重新连接任务状态。取消应终止下载和当前 FFmpeg worker，释放 Blob 与临时数据，并能执行后续任务。

## 权限与本地边界

计划权限为 downloads、storage、offscreen、必要的 declarativeNetRequest 权限，以及 B 站 API/媒体域名的最小 host_permissions；实际清单按实现验证进一步缩减。无需 nativeMessaging、Cookie 导出、全站访问或本地服务端口。仅允许 B 站页面及扩展自身发起受支持动作，网页不能把扩展变成任意 URL 下载代理。

代码、依赖缓存、测试浏览器数据、构建产物都放在本项目目录。安装由用户在 Chrome 扩展页面加载目录完成，不修改用户 Chrome 配置文件或系统设置。

## 实现修订附录：原始轨流式临时文件（2026-10-24）

实站排查发现，将 CDN URL 直接提交给 Chrome 原生下载时，所需的扩展请求头规则不能可靠作用于该下载，可能返回 403。原始轨改为 offscreen 发起 fetch、流式写入 OPFS，再把本地 File / Blob URL 交给 Chrome 保存。最终验证范围及结果由 `docs/TEST_REPORT.md` 记录。

该路径保持原始字节，不经过 FFmpeg，也不应用 512 MiB 合并 / 转码输入预算；它仍受磁盘剩余空间、浏览器来源存储配额、网络及源站限制。保存时临时副本与最终文件可能同时占用空间。

完成、失败和取消时释放 Blob 并清理临时文件；异常退出留下的文件在下次原始轨任务开始时清理。保存完成前保留文件和 Blob，以免 Chrome 正在保存的数据失效。此机制是临时存储，不提供跨浏览器退出的断点续传；重试重新获取资源并下载。原始音轨导出同样采用此路径。
